## 一、原始定案（移出前原文，一字未改）

### 1.1 导航要点（原 §五）

> 全局：A*/Smac 在分层 costmap 上 + 层间图（不是一张 2D 平面连续规划）。
> 局部：DWB（局部规划器）/ RPP（**实为路径跟踪 Controller，非局部规划器**；低速慢平台上算力友好）；
> 不引入 MPPI（避免与感知推理抢 CPU 核）。
> 语义化：静态障碍来自场地几何（已建成塔=障碍，空地=可行），动态障碍来自融合语义目标。

### 1.2 多层 costmap（原 §十 第 4 条，方向定案）

> **4）多层 costmap：每层独立 2D costmap + 层间转移边构成的图，不用 3D voxel。**
>
> 综述完全未覆盖此议题。结构：`[地面 2D]` ——坡道 / 楼梯边—— `[L1 2D]` ——L2 阶梯边—— `[L2 2D]`；
> L1 边缘设禁入带防坠落。理由：CPU 开销低、Nav2 生态成熟、BR 为低速差速平台，
> 全景 3D voxel 在本机上是自残。

### 1.3 排期位置（原 §九 Phase 2）

> Phase 2：定位（Point-LIO + 先验）+ **多平面 costmap + 局部导航**。
> （2026-09-20 注：原文 "FAST-LIO2" 系笔误，现役算法全线是 Point-LIO —— 见任务书 §十四）

### 1.4 相关：§十 引言里对这块的定性

> 四份算法综述（SLAM / 雷达点云 / 机器视觉 / 路径规划）已通读；它们对本项目最关键的
> 四处空白是：**多层 costmap**、Livox 非重复扫描、3D 已知地图定位、比赛光照鲁棒性
> —— **均无现成方案可抄，只能自研**。

## 二、它想解决什么问题

| 问题 | 本方案的回答 |
|---|---|
| 场地有 L1(600mm) / L2(900mm) / 楼梯 / 坡道，**一张 2D 栅格表达不了"上楼梯"** | 每层一张独立 2D costmap，层与层之间用**层间转移边**连成图 |
| 目标点不固定（决策层在线选点） | 在线跑 A*/Smac 全局规划 |
| 有动态障碍（对手、被建的塔） | 代价地图 + 局部规划器（DWB）实时绕行 |
| 防坠落 | L1 边缘设**禁入带** |
| CPU 有限 | 每层 2D（不用 3D voxel）；不引入 MPPI（避免与感知推理抢核） |

## 三、为什么没进主线（移出理由）

### 3.1 这个场地几乎不需要"找路"

- **场地完全已知** —— 官方总装配 STEP 已解析进 `config/field_geometry.yaml`，坐标逐条核对过
- 起点 / 终点 / 途经点**赛前都能精确测量并写死**
- 可选的落点是小而固定的集合：启动区、存储区、转运区、10 个建造位、共享区、楼梯口/坡道口

→ A* 在解一个"如何从 A 到 B 找一条最优路"的问题，而这里 90% 的路径**不需要"找"**。

### 3.2 对手被物理隔开

- 中轴隔墙地面段跑满 `y[0,11]`（`center_divider.ground_y_range`）
- 规则 **6.2.2** 禁止机器人进入对手领地
- **只有 3 处共享区双方都能进**（地面共享区 / L1 共享区 / L2 共享区）

→ 全场动态避障的需求**大幅缩小**，只剩共享区那 2-3 块的局部行为。

### 3.3 180 秒需要确定性

在线规划每场的路径与耗时都会变，难以离线测准；比赛现场排障也复杂得多
（costmap / planner / controller / recovery / TF / QoS 层层可能出错）。

### 3.4 最贵的那块没有参考

**多层 costmap 是本项目四处"无现成方案可抄，只能自研"的空白之一**（见 1.4）。
把它塞进主线，等于把最大的不确定性放在关键路径上。

### 3.5 跨层问题可以离线解决

多层/楼梯/坡道这一点**是真的**，但它不需要在线规划来解 ——
场模已经把全部跨层点给出来了：

| 跨层 | 场模字段 | 我方（红 / 西） | 对方（蓝 / 东） |
|---|---|---|---|
| 地面→L1 **楼梯**（3 级 ×150mm） | `stairs.ours.from_xy` → `to_xy` | (1.5, 2.8) → (1.5, 3.7) | (9.5, 2.8) → (9.5, 3.7) |
| 地面→L1 **坡道**（3.5m，9.7°） | `ramp.ours.low_xy` → `high_xy` | (2.0, 8.2) → (2.0, 4.7) | (9.0, 8.2) → (9.0, 4.7) |
| **L1→L2 阶梯**（1 级 ×150mm） | `l1_l2_stairs.ours` | 西条 `x[3.7,4.0]`, `y[5.0,6.0]` | 东条 `x[7.0,7.3]` |

**离线把路网建好，"层间图"这个想法就保留下来了**，只是从"规划器的内部结构"变成"路网本体"。

## 五、A/B 怎么比

| 阶段 | 判据 |
|---|---|
| 离线 | 路网/图层建得对不对，看一眼图就知道 |
| 仿真 | Gazebo 里按序走完 N 个点 |
| 真机 | 到点精度 + 全程不撞 |
| 跨层 | 楼梯、坡道**各至少走通一次** |

**建议先做静态层** —— 从 `field_geometry.yaml` 直接烘出 costs 图层（L1/L2 台面、楼梯、坡道、
隔墙、柱子、围栏），场地数据现成，产出最快，能马上在 RViz 里看到一张真场地的 costmap，
**图层划分错没错看一眼就知道**，不用等整套跑起来才发现。
