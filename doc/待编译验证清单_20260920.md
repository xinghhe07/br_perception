### I. **运行时**验证 —— 本批最该测的一条

```bash
# 起相机层（默认: 单容器 + 不开 D435i）
ros2 launch br_perception bringup_debug.launch.py perception_rviz:=false

# 另开
ros2 topic hz   /perception/camera/frame
ros2 topic echo /perception/camera/frame --once
```

**判据（依次）**：

1. **帧率** ≈ `frame_rate_hz`（默认 30Hz）。取不到 → 看容器日志里 `CameraPerceptionNode ready` 那行有没有打出来。
2. **`slot_status` 有 8 个**，每个的 `kind` / `camera_id` 与下标对得上（`[0]=mustika_wide` … `[6]=depth`）。
3. ⭐⭐ **回归验证（**这是本次改动最该测的一条**）**：
   ```
   故意停掉一路检测器（Ctrl-C 掉，或给它发一个不存在的输入话题）
   → 该路对应槽的 stale_sec 应该**持续增大**、state 变成 S_STALE(2)
   ```
   > ⚠️ 若 stale_sec **恒为 0**、state 恒为 FRESH —— **说明修错了**。
   >    这正是初版的 bug：`stale_sec` 的基准错设成"各槽里最新那个 stamp"，
   >    于是所有检测器同时停发时，那个"最新槽"也跟着停住，恒报 FRESH ——
   >    **把要暴露的失效模式掩盖掉**。现在基准是**组帧时刻**，必须往上走。

   ⚠️ **"健康的槽"长什么样，先记下来免得误判**：
   - `stale_sec` 是**小的正数**（≈ 该检测器的处理耗时 + 传输，量级 20~40ms），
     **不是 0** —— 曝光时刻永远早于组帧时刻，恒为正才正常。
   - `state` = `S_FRESH(1)`，直到 `stale_sec` 超过 `fresh_tolerance_sec`（默认 **0.5s**）。
   - 所以停掉检测器后，**约半秒**才会翻成 STALE，不是立刻。
     嫌慢/嫌误报就调 `fresh_tolerance_sec`（它按秒给，就是为了别把"正常但慢"判成 STALE）。
   - ⚠️ 若健康的槽也一直报 STALE → 多半是 `fresh_tolerance_sec` 被调得比
     检测器正常周期还小了（或填了 0，会被下限抬到 0.01s）。

4. **哨兵值**：从没来过数据的槽，`stale_sec` 应为 **0** 且 `state = S_NEVER(0)`（不是负数、不是天文数字）。
5. **深度槽**：默认恒为 `MODE_IDLE`，`depth_measuring == false` —— **这是正常的**，因为 `/camera/depth/target_roi` 在本 launch 里没有发布者。要测 MEASURE 通路：
   ```bash
   ros2 topic pub --once /camera/depth/target_roi sensor_msgs/msg/RegionOfInterest \
     "{x_offset: 600, y_offset: 300, width: 80, height: 80, do_rectify: false}"
   ```
   然后看 `depth_measuring` 是否变 `true`。

**`ProjectGeometryTest` 这 6 条是 2026-09-24 新加的投影几何**，全部**手算得出答案**
（期望值不是"跑出来是什么就写什么"）：
- 相机在塔顶正上方朝下看 ⇒ 顶面中心必须落在 **(cx, cy)=画面正中**、边长 = `fx·0.2/1.10 = 94.9px`
  ⇒ 这条挂 = **坐标系约定错**（机身系/光心系 90° 那步），**别去调内参**。
  同一条还钉 `grazing_deg≈0`、`distance_m≈1.10` —— 见下面第二个真错。
- 水平平视 ⇒ `face_h_px ≈ 0`（门控该拦）；同一条还断言**宽度几乎不变**（116px）——
  ⇒ 这就是"掠射看高度、不看宽度"的理由。⚠️ 这条记的夹角是 **90.00°**（与顶面同高）。
- `scale=0.5 pad=20` ⇒ 尺寸减半、中心按 `x·0.5+20` 平移 ⇒ 挂 = **letterbox 方向抄反了**。
- 相机**背对**塔 / 方块**出画** / 参数非法 ⇒ 一律 `valid=false` 且 `note` 里有话。
  ⚠️ "背对"那条**原先恒挂**（它只改四元数不改平移 ⇒ 变换不自洽、隐含的相机绕到了
  另一侧**正对着塔**）—— 已修成自洽的变换。看到它红，先看这条注释，别怀疑环境。

⚠️ **写单测这条路上抓到的真错**（先记在这，免得又犯）：
1. 投影的平移约定我写成了 `p_cam = R·(p−t)`，而 tf 的约定是 **`p_cam = R·p + t`**
   （`t = −R·p_cam`，不是相机位置）。症状：**所有点落到光心背后 ⇒ 投影恒失败**。
   是靠上面那条"落在画面正中"的手算用例、在本机用 Python 复现同一公式抓到的。
2. ⚠️⚠️ **掠射角的方向与参考点都反了**（2026-09-24 复核抓到，已修）：`grazing_deg`
   写成了"**相机→方块**"且参考点取**方块中心**，而判据要的是"**方块→相机**"+
   "**顶面中心**" ⇒ 相机在塔顶正上方（最好的位置）算出 **180°**、距离算出 1.20m，
   于是门控 `>= 89°` **把最好的位置拦掉、把最坏的位置放行**。
   症状会是"**判出来的颜色不是顶面的颜色**"（比判不出来贵得多）。
   ⇒ 这是"期望值必须手算"的第二个理由：这一处**读代码时很像对的**。
   （对照：`ProjectGeometryTest` 里"正上方朝下看"那条的 `grazing_deg≈0` / `distance_m≈1.10`、
   "水平平视"那条的 `90.00°` —— 它们就是钉这两处的。）

## 2. 仿真端到端（**本轮唯一能验判色链的路子**）

```bash
# 三个 launch，三个终端（点云/里程计/传感器 TF 由第一个提供）
ros2 launch br_perception bringup_gazebo.launch.py
ros2 launch br_perception bringup_lidar_only.launch.py livox:=false lio:=false use_sim_time:=true
ros2 launch br_perception bringup_debug.launch.py sim_camera:=true use_sim_time:=true

# 起来后先验这两条（都在本轮的改动里）:
ros2 run tf2_ros tf2_echo odom base_link     # 静止时应为 (0.35, 0.35) ← 出生位姿
ros2 topic echo /perception/camera/sky_blocks_tele --once   # 看 roi_source / spot_id 字段
```

**验收判据**（三条，按价值排）：
1. **车离开原点转个弯之后**，建筑位仍然量得对 —— 这是**坐标系修复的唯一验收姿势**
   （车停在原点时两个系恰好重合，**修了跟没修一样**）。
2. 场上**没有塔**时：相机不该发任何 `detected=true` 的判色消息（雷达不报完整塔 ⇒ 主路不投影）。
3. 造一座塔（把天空块放到 L1 位上叠成 0.90m）：相机应能报出颜色；
   ⚠️⚠️ **前置条件：相机必须高于塔顶** —— 塔建在平台上（L1 位 z=0.6）⇒ 塔顶在 **1.50m**，
   而仿真相机在 **0.60m**（`models/fishbot/model.sdf` / `SENSOR_TF`）且 **pitch=0 平视**，
   **比塔顶低 0.9m**。那种位置**物理上看不见顶面**，正确行为是**恒报 `GRAZING_ANGLE`**
   （动作: 换位姿/靠近）—— **不是"判色链坏了"**。要真看到颜色，二选一：
     · 把仿真相机抬到 **>1.5m**（验 L2 位要 **>1.8m**）—— 注意 `SENSOR_TF` 与 SDF 的
       `<pose>` 两处要一起改，且内参按 SDF 的 hfov 推（见 `bringup_debug` 的 `SIM_INTRINSICS`）；
     · 或把这座塔建到**地面**上，同时把相机抬到 **>0.90m**（塔顶多高、相机就要多高以上：
       地面塔顶 0.90 ⇒ 门槛 0.90；L1 塔顶 1.50 ⇒ 门槛 1.50。**"相机要高过塔顶"是硬约束**，
       与塔建在哪无关）。
   ⚠️ **若恒报 `RATIO_AMBIGUOUS`（红蓝≈各半）⇒ 模型/实物不对，不许放宽 `decisive_ratio`**
   （见 `field_geometry.yaml` 的裁定 + 台账 §八 9.4）。
