## 2. 今天改了什么（逐项）

### A. 三个 msg 加了 `header`（**会影响依赖它们的代码**）

```
msg/CameraMustika.msg       + std_msgs/Header header
msg/CameraPillar.msg        + std_msgs/Header header
msg/CameraBuildingSpot.msg  + std_msgs/Header header
```

**已核**：这三个 msg **只在自己的检测器里构造**，无其他消费者、无单测。
→ 检测器里都已补 `out.header = msg->header`（继承曝光时刻）。

### B. 两个新 msg

```
msg/PreprocessedImage.msg   （新）预处理图 + letterbox 变换五字段
msg/CameraDepth.msg         （新）D435i 深度辅助
```

### C. 反投影反算链路（P0-3，今天的主体）

```
相机驱动 → sensor_msgs/Image → image_preprocessor → PreprocessedImage → 4 个检测器
```

- `image_preprocessor` 的**输出**类型从 `Image` 改成 `PreprocessedImage`
- **4 个检测器**的订阅类型、回调签名、`toCvShare(msg->image)` 全改了
- 检测器**发出去之前**把 bbox 反算回原图坐标（`letterbox_to_orig_xy` / `_size`）
- `image_preprocessor.hpp` 新增三个 `inline` 反算函数

### D. 相机改名（front/rear → wide/tele）

全仓库 313 处。**`camera_front` → `camera_wide`、`camera_rear` → `camera_tele`**。

⚠️ **如果你本地有旧的 bag 或 launch 覆盖文件，话题名会对不上。**

### D2. 相机硬件规格拆成独立文件（2026-09-21 VM 发现后补的）

**VM 报"`camera_params.yaml` 第 5 节导致整份加载失败"** —— 根因：

> ROS 2 params 文件要求**每个顶层键都是节点名且带 `ros__parameters:`**，
> 而 `camera_wide:` / `camera_tele:` / `camera_depth:` / `model_backend` / `model_path`
> 都没有 → 解析器直接报错。

**修法**：把第 5 节整体拆到 **`config/camera_hardware.yaml`**（纯 YAML，不是 params 文件）。
`camera_params.yaml` 现在只剩 4 个节点块，全部合规。

⚠️ **两个标定脚本的读写目标也跟着改了**（`calibrate_camera.py` / `calibrate_lidar_camera.py`）
—— 它们现在读写 `camera_hardware.yaml`。

### E. 通信波特率

```
config/comm_params.yaml                       115200 → 460800
serial_manager.hpp   int baud_rate{115200} → {460800}
```

`serial_manager.cpp` 的 `to_speed()` **本来就支持 `B460800`**，不用改。


### ④ 反投影反算链路（**今天最该验的**）

**不开相机也能验一半** —— 起预处理节点，看它发的话题类型对不对：

```bash
ros2 run br_perception image_preprocessor --ros-args \
  --params-file install/br_perception/share/br_perception/config/camera_params.yaml
# 另开一个终端
ros2 topic info /perception/camera_wide/preprocessed
```

**判据**：
- 话题类型是 `br_perception/msg/PreprocessedImage`（**不是** `sensor_msgs/msg/Image`）
- 有相机的话，喂一张图进去，看 `scale` / `pad_x` / `pad_y` / `orig_w` / `orig_h` 五个字段有没有合理值

**最直接的验法**：拿一个已知尺寸的东西（比如一张 A4）拍一张，看反算回来的坐标对不对。
没有相机的话 —— **至少确认话题类型对得上，检测器能收到**。

### ⑤ camera_depth_node（全新，**没有硬件也能起**）

```bash

# 另开

```

**判据**：
- 节点能起来，**没崩**
- 没有深度输入时，**1Hz 心跳**在发（IDLE 模式）

有 D435i 的话，再喂一个 ROI：

```bash

  '{x_offset: 200, y_offset: 150, width: 200, height: 150}'
```

**判据**：应该切到 `mode=1`（MEASURE）并开始发 `/perception/camera/depth`。
